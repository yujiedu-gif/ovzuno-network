## What does “Eden token” refer to?

A project name or token label is not, by itself, a unique on-chain identity. For an Ethereum ERC-721 token, for example, the identifying pair is the smart-contract address and token ID on an Ethereum chain. This is a standard-specific example; it does not show that an Eden-branded asset is an ERC-721 token.

A careful identification begins with primary project materials that state the token’s full name and ticker. The next step is to check whether those materials provide a network and contract address, then compare those identifiers with records on that network. The evidence available here includes no Eden project documentation or network record to perform that check. As a result, it cannot establish which asset, if any, the phrase refers to.

This distinction matters because names and symbols are labels, while a contract address identifies a particular deployed contract in its network context. Even a verified address would establish an on-chain identifier, not every claim about the project, the token’s rights, or its operation. If two sources use the same name but provide different network or contract details, that discrepancy should be reported as unresolved rather than treated as proof that the entries refer to one asset.

For now, similarly named listings should not be assumed to describe the same token. Without a documented identifier and matching network record, the name “Eden token” cannot reliably connect a reader to a specific project or deployment.

## What should readers verify before relying on token information?

Use separate checks for identity, technical details, and project claims. A practical review can proceed in this order:

1. **Find the primary project statement.** Look for documentation that gives the token’s full name and stated ticker and clearly identifies the project making the claim. No such Eden-specific source is available here.
2. **Match the network and address.** Check whether the documentation names a network and supplies a contract address, then compare those details with records on that network. A project name or ticker alone does not establish that a deployment is the one described.
3. **Confirm the standard and interface.** Only after the contract is identified should a reader assess whether a stated token standard applies. An example from EVM integration illustrates why this check depends on exact technical details: the application must use an ABI matching the deployed contract interface and network address. The evidence here does not identify an Eden contract or ABI.
4. **Separate intended functions from demonstrated behavior.** Read what the project says a token does, note any conditions or limits, and avoid turning a general description into a claim that the function is available or guaranteed. No Eden-specific function or limitation is verified here.
5. **Demand support for operational claims.** Supply, distribution, fees, audits, security properties, custody, recovery options, and availability each require evidence relevant to the particular asset and arrangement. The available Eden evidence establishes none of them. A provider-specific security description, for instance, may describe key generation and signing inside an isolated trusted execution environment, but that architecture does not eliminate application, credential, policy, provider, or recovery risks. It is not evidence about Eden.
6. **Keep rights and jurisdiction questions separate.** No legal rights, redemption terms, regulatory classification, tax treatment, or compliance status for an Eden token are established here. Those questions require current, authoritative evidence for the relevant arrangement and jurisdiction; this explainer does not assess them.

If project materials and network records disagree, preserve the disagreement as a question to resolve. Do not choose one identifier merely because it appears in a more prominent listing. Likewise, a source that describes a network or a software tool should not be treated as independent confirmation of a particular project’s token.
