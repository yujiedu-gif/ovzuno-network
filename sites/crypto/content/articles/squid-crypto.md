## How to distinguish similarly named projects and tokens

Begin with the exact source where the name appears. Record how it describes the item: is it presenting a project, a protocol, a service, or an asset? Then seek documentation attributable to that project that explicitly connects the name with the described purpose and, where applicable, technical identifiers.

For a token, a name or ticker is not enough to distinguish it from another asset with a similar label. Compare the network and contract address, if the project identifies them, and check that the description and identifiers agree across the materials being considered. Treat an identifier as useful only when its connection to the claimed project is documented; finding an address somewhere does not, by itself, establish that the project endorses or controls it.

For a protocol or service, check whether its documentation names the system and describes the specific functionality being claimed. Do not transfer a technical detail from a different product merely because its name sounds similar. For example, a documented property of an unrelated implementation remains evidence about that implementation, not about a Squid-branded item whose identity has not been established.

A practical comparison can use these steps:

1. **Capture the claim and its source.** Note the exact name, what the source says it refers to, and where that statement appears.
2. **Locate attributable project documentation.** Look for an explicit connection between the name and the specific project, protocol, or asset being described.
3. **Compare identifiers.** For an asset, check the stated network and contract address when available. For a protocol, compare the named system and its documented operation.
4. **Look for consistency.** Confirm that the sources being compared use the same identifiers and describe the same item. A discrepancy should be explained by an attributable source, not resolved by assumption.
5. **Keep unresolved cases unresolved.** If the link between the name and identifier is missing or conflicting, do not present the match as confirmed.

A separate caution concerns claims about decentralization. The number of nodes alone does not show whether operators are independent, geographically diverse, or running diverse implementations, or how block-production power is distributed. This general limitation is not evidence about any particular Squid project; it is a reason not to treat a broad architecture label or a simple count as a complete description of a system.
