When reviewing materials, distinguish the ticker, the token, the project describing it, and any broader platform or service. A project might describe a platform with several functions, but that description alone does not show that the token performs each function. Similarly, a project name or ticker does not identify a token’s network or contract address.

Treat identity as a connection that needs evidence: a current project source should name the asset and explain its relationship to the project; network records should then be checked against the specific network and contract the project identifies. For each identity statement, record the source, its date, and the scope of what it says. A statement about a project or service is not automatically a statement about the token. A statement about an older token contract or product version is not automatically current.

## How to verify STPT’s documented role

Begin with primary project documentation that explicitly names STPT. Next, separate intended utility from demonstrated operation. A statement that a token is meant to support a particular use does not, on its own, show that the use has been implemented, is currently available, or is being performed by an application. A technical claim should be supported by documentation and network data that match the token, the relevant contract, and the particular function being described. No such STPT-specific evidence is available here.

This distinction helps avoid scope creep. Evidence that a platform has a feature does not establish that the token is required for it. Evidence that a contract can perform an action does not show that a particular application uses that action. Evidence from one version does not establish behavior across other versions. If documentation omits a date or does not clearly define the subject of a claim, avoid describing it as a current, token-specific fact.

A useful review note can state the claim, identify whether it is a project assertion or a technical observation, record the source date, and specify the token, network, contract, or product version involved.
