## How the named-entity question differs from mining consensus

A consensus process is a set of network rules and mechanisms used to determine how participants propose or accept a shared history. In proof of work, computational work is used to propose candidate blocks. Bitcoin’s design illustrates this: a miner varies a nonce in a block until the resulting hash meets the network’s target condition. This example describes Bitcoin’s mechanism; it should not be treated as a universal specification for every cryptocurrency network. [^1]

Mining software can also transform block-template information into block-header work for hashing hardware to search and report. This is a technical workflow, not an identification of any particular company, facility, or service. [^2] The protocol defines the network’s process. A provider, if involved, would be a separate organization or service whose role would need to be established from its own documentation.

This distinction helps prevent two different questions from being collapsed into one. “How does this network’s proof-of-work process operate?” is a protocol question. “What does a company called Compass provide now?” is an entity and service question. A general explanation of proof of work cannot verify a provider’s current offerings, and a provider’s name cannot establish how a network’s consensus rules work.
