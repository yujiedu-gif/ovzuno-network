## Why the name GLOW needs disambiguation

A name or ticker is a search clue, not proof of a unique asset. Similar labels can appear in different project descriptions or on different networks. A project’s use of a name does not, by itself, identify the on-chain record connected to that project. Reliable identification requires evidence that links the project’s stated asset to a particular network and identifier.

The identifier depends on the asset format. For example, on an Ethereum chain, an ERC-721 token is identified by the combination of its contract address and token ID. Its name, symbol, and image are not reliable global identifiers. This describes one standard’s identification model; it is not evidence that a GLOW asset is an ERC-721 token or exists on Ethereum. ([source](<https://eips.ethereum.org/EIPS/eip-721>))

Metadata can offer recognition clues, but it is not a substitute for the identifier. An ERC-721 metadata extension can associate a token ID with a URI referring to metadata. That standard does not guarantee that the referenced information is available, permanent, accurate, or licensed. It also does not establish that a GLOW asset uses the extension. ([source](<https://eips.ethereum.org/EIPS/eip-721>))

The practical distinction is between a label and a verifiable match. A label may help locate a candidate; the network and identifier are needed to test whether that candidate is the asset described by the project. If those details are missing or conflict, keep the candidate unconfirmed rather than merging information from different records.

## How to verify the token’s identity

Begin with primary project materials that explicitly identify the asset. Look for an official document or announcement naming the network and giving the contract address, mint, or other identifier where applicable. The materials should connect those details to the project’s stated token. A search result or third-party listing that repeats “GLOW” does not provide that connection by itself.

Then compare the project-provided identifier with a public record for the named network. A block explorer is one kind of interface for inspecting on-chain activity, but the relevant record must match the network and identifier in the project materials. Do not assume that a record associated with a similar name belongs to the project you are researching.

Keep project statements and observable records separate. Project materials can describe what the project says an asset is intended to do. A blockchain record can show information associated with a particular on-chain identifier. A matching record may help establish that the identifier exists on that network, but it does not independently prove a project’s claims about purpose, rights, backing, or safety.

Record the evidence in distinct fields: the project name as presented, the network, the exact identifier, and the source supporting each detail. If one source gives a contract address but does not state a network, or if another source names a different identifier, note the gap or conflict. Do not combine partial details into a confident identification.

Network context matters even when labels match. Provider support for a token deposit can depend on the specific chain and token representation; a symbol match does not establish that a provider recognizes or supports a particular asset. This is a general caution about chain-specific support, not a statement about GLOW or any particular provider. ([source](<https://developers.circle.com/circle-mint/supported-chains-and-currencies>))
