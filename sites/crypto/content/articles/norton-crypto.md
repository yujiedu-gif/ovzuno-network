## How Norton Crypto relates to proof-of-work mining

Proof of work is a consensus model in which a participant performs a computational problem that is costly to solve but straightforward for other network participants to verify. The process consumes time, energy, and computational resources, and a network’s specific rules determine how it operates. Bitcoin is one example; this general definition should not be treated as a universal description of every cryptocurrency network. ([source](<https://csrc.nist.gov/glossary/term/Proof_of_work_consensus_model>))

In Bitcoin’s design, proof of work helps order competing transaction histories. When histories compete, nodes select the valid chain with the greatest cumulative proof of work. Validity still matters: accumulated work does not make an invalid block valid. ([source](<https://bitcoin.org/bitcoin.pdf>))

A Bitcoin-specific example illustrates where software can fit. Mining software constructs a candidate block and block header from transactions, then sends header work to hashing hardware. The hardware searches for a result that meets the network’s proof-of-work condition. This describes a documented Bitcoin workflow, not a confirmed Norton Crypto workflow. ([source](<https://developer.bitcoin.org/devguide/mining.html>))

The distinction is between protocol and product. A protocol defines the network’s consensus rules; a branded feature is a product layer that might interact with a network. Knowing the general proof-of-work process does not establish which network Norton Crypto supported, how it created or assigned work, whether another service was involved, or how any resulting rewards were processed. None of those product-specific mechanics is verified in the evidence available here.

This boundary matters when interpreting broad descriptions.
