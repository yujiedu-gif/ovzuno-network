## Evidence to check before relying on product claims

First, look for documents that establish identity: a manufacturer name, exact model designation, product page, manual, and a support channel attributable to that manufacturer. These should be consistent with one another and clearly apply to “Starsign Crypto USB Token S,” rather than to a different model or a general product family. If no such documents can be tied to the phrase, stop short of treating it as a confirmed product identity.

Next, examine the documentation for operational detail. It should explain what the device does, how it interacts with other software, and which functions are handled by the device versus a wallet, application, provider, or user. For example, a claim that the device handles keys should specify what key material it handles and for which operations. A claim that it provides authentication should identify the system or process being authenticated. A broad statement such as “crypto security” does not answer either question.

Security claims need evidence appropriate to their scope. Product documentation should identify the relevant security architecture, key-handling model, and firmware practices. If an independent assessment is cited, check which product version and components it examined, what methods or questions were in scope, and what limitations it reported. Evidence about one component or configuration should not be treated as a conclusion about every product use or the security of an entire crypto system.

Other statements also need current and relevant support. Compatibility depends on the named device and the software or system in question. Availability, fees, yields, and performance are not established by a product name or generic description. If the evidence does not identify the product, version, conditions, and source for a particular claim, report that claim as unverified rather than filling in the gap.

Conversely, a device described as handling keys would need documentation explaining which operations those keys support. The available evidence does not establish that “Starsign Crypto USB Token S” performs either function.

If product documentation claims key handling, review the whole path: what the device does, what companion software does, and what actions require user authorization. Look for information about backups, recovery, and the consequences of device loss, damage, or failure. Do not assume that a backup exists, that a replacement device restores access, or that recovery is possible unless product-specific evidence explains the procedure and its limits.

Self-custody describes an arrangement in which the user controls the private keys and recovery material needed to access the user’s crypto assets. It is a responsibility model, not a feature that can be inferred from a USB connection or a product label. Nor does the general definition verify a particular device’s recovery process. [source](<https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins/crypto-asset-custody-basics-retail-investors-investor-bulletin-0>)
