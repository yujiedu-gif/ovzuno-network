Pi cryptocurrency is a name that may refer to a token, the network associated with it, or the broader project. These terms are related but not interchangeable: the token is an asset or unit, while a network is infrastructure for handling records and activity. The evidence available here does not establish Pi-specific network design, token functions, or current access conditions, so readers should verify those details in current primary documentation rather than infer them from the name.

## What Pi cryptocurrency means

A cryptocurrency, in a technical definition, is a digital asset, credit, or unit that can be cryptographically transferred between users of a blockchain network. This describes a general category; it does not verify the design or operating status of any particular project. [source](<https://csrc.nist.gov/glossary/term/Cryptocurrency>)

In a Pi-specific discussion, “Pi” may mean the token, the network, or the project as a whole. A source might use the name for the asset, refer to software or infrastructure, or describe a related application or service. The name alone does not tell readers which meaning is intended. When assessing a claim, identify its subject: is it about a token record, a network function, a wallet, an application, or the project more broadly?

The distinction matters because an asset’s existence does not establish all the functions or services that may be associated with it. For example, the ERC-20 standard defines a common interface for balances, direct transfers, and approvals that let another address spend up to an authorized amount. That interface does not determine issuance policy, backing, market value, compliance, or code safety—and this general example does not establish that Pi uses ERC-20. [source](<https://eips.ethereum.org/EIPS/eip-20>)

## How the Pi token relates to the network

A token is the asset or unit; a network is the infrastructure that can record or handle activity involving it. The terms therefore describe different parts of a system, even when people use the same name for both. The evidence available here does not specify Pi’s network design or document a particular function of its token. General descriptions of crypto networks should not be presented as verified descriptions of Pi.

It is also useful to distinguish a network from the applications and services built around it. An Ethereum application stack, for example, can include blockchain nodes and smart contracts, as well as client libraries, wallets, front-end interfaces, data indexing, storage, and other off-chain services. A particular application may use only some of these components and rely on centralized providers for others. This illustrates why a project name or token reference alone does not identify every component involved; it does not establish which components Pi uses or who operates them. [source](<https://ethereum.org/developers/docs/ethereum-stack/>)

A token record also does not, by itself, settle what the token represents or what rights, functions, or services are available. The distinction between an on-network record and other systems or terms is especially important when a claim concerns an asset associated with something beyond the token itself. ## What to verify about operation and access

For any claim about Pi’s operation, first determine exactly what is being described: the network, the token, a wallet, an application, or an outside service. Then consult current primary documentation that explains the stated function and any conditions. A project description is not, on its own, evidence that a particular service is available or that an outside provider supports it.

Keep the source of an operational claim clear. A statement about a network record may not establish whether a wallet or application supports a related action. A statement about an outside service may describe that provider rather than the network. The evidence available here does not establish Pi-specific exchange support, wallet compatibility, transfer availability, or fees. Omit those specifics unless current, attributable documentation supports them, and preserve any limits or conditions the documentation states.

Availability is a question to verify, not a conclusion to draw from the word “token.” A token’s existence does not establish that every related network function or transfer is currently available. Nor should a statement about one component be extended to the whole project without evidence. For example, documentation about a wallet would need to be understood as documentation about that wallet, not automatically as a description of network-wide operation.
