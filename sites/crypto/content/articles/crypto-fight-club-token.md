## How to verify a Crypto Fight Club token’s identity

Start with primary project materials that name the token and state its network and contract address. Then inspect attributable records for that address on the stated network. A block explorer can provide an interface for inspecting blocks, transactions, accounts, contracts, tokens, and other on-chain activity, though explorer fields and terminology differ across networks and providers.

Next, compare the records rather than relying on a single label. Check whether the project-controlled materials link to the same contract address and network that appear in the explorer. If the address is missing, the network is unclear, or the materials and records disagree, leave the identity unresolved. Do not choose whichever result has the most familiar name, ticker, or logo.

Record where each detail came from and when it was checked. This is especially useful for claims that may change, such as a project’s stated links or current documentation. The evidence available here does not provide a dated, attributable Crypto Fight Club address to compare, so this article cannot report a successful identity match.

Keep source types separate. Project documentation supports a statement about what the project claims. An explorer record supports a statement about information recorded on a particular chain. Neither source automatically verifies every other kind of claim. For example, documentation about an intended feature is not, by itself, proof that the feature is operating, while an on-chain record does not by itself establish the truth of a statement about an off-chain service or relationship.
