## How to verify the token’s network and contract identity

A focused identity check begins with a source that can be attributed to the relevant project, issuer, or protocol. Look for an explicit network name and contract address. Then compare those details with a record for the same network. The evidence available here does not provide those identifiers for Chedda, so it cannot support a positive identification.

Network context matters. A contract address should not be treated as a complete identifier when the network is missing. Likewise, a matching name or ticker does not show that records on different networks refer to the same asset. Token support can be specific to a chain and token representation; an asset sharing a symbol with another token does not establish that it is the same supported representation. [source](<https://developers.circle.com/circle-mint/supported-chains-and-currencies>)

When checking sources, keep the project documentation and network record side by side. Confirm that the network names match and that the contract address is identical. If one source uses a different address, omits the network, or cannot be tied to the project, record the discrepancy rather than selecting whichever reference appears most often. Popularity or repetition does not resolve an identity mismatch.

Record the source and date checked, too. This makes the conclusion auditable and helps distinguish a current reference from an older or superseded one. ## A practical evidence checklist before relying on a token description

For a bounded identification check, keep a short record of the evidence and its gaps:

- **Project source:** Note the attributable project or issuer document, if one is available, and when it was checked. If attribution is unclear, say so.
- **Network and identifier:** Record the network name and contract address stated by the project source. Do not assume a name or ticker is unique.
- **Matching network record:** Compare the project’s identifiers with a record from the same network. An address on an unspecified network is incomplete evidence.
- **Stated purpose:** Quote or accurately summarize what the documentation says, and label it as a project description. Do not turn an intended function into a claim of demonstrated operation.
- **Unresolved claims:** List conflicts, missing identifiers, or unsubstantiated statements about availability, legal status, compliance, fees, yields, security, audits, backing, redemption, or recovery.

If a source and a network record conflict, preserve the conflict in the summary. If the source supplies no identifier, mark the identity as unverified. If the only support is a matching label or symbol, that does not close the gap. These are evidence-handling steps, not a recommendation to acquire, trade, or use an asset.

For legal, tax, or security decisions, this identification alone is not a sufficient basis; the relevant question requires qualified, situation-specific review.
