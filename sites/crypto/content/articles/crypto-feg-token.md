## What to confirm before relying on token information

Use this bounded checklist when a source discusses FEG:

1. **Identify the source.** Look for project documentation that can be attributed to the project and that specifies the token being discussed.
2. **Record the network and exact address.** Do not treat a ticker or name as a substitute for both details.
3. **Cross-check the same address on that network.** Compare the available contract or token records with the project’s stated details; report discrepancies rather than resolving them by assumption.
4. **Note the information date.** A claim about current identity or function requires evidence relevant to the time it is being relied on.
5. **Separate stated purpose from verified behavior.** Attribute function claims to the project unless evidence independently establishes more.
6. **Leave unsupported matters open.** Do not infer availability, fees, yields, recovery options, audits, security status, administrative controls, or compliance requirements without separate, current evidence with the appropriate scope.
