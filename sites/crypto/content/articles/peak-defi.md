## How to assess the available evidence

A bounded assessment begins with identity. Look for attributable materials that name the entity and describe its stated purpose. Then check whether those materials connect the name to specific technical records, rather than merely presenting records that resemble something associated with the project. Keep project statements separate from what the records independently demonstrate.

For each material claim, record the source, date, scope, and limitations. If an API exposes a category of data, that is evidence about the API’s coverage, not automatically about a named project. If a framework evaluates a particular class of system, first establish that the project belongs to that class before using the framework to describe it. If a document makes a security or operating claim, preserve its scope and do not generalize beyond what it assesses.
